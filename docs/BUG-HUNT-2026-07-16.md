## Sibling-sweep

**BH-13** — pattern signature: a socket hook's `connect`/`connect_error` self-heal handler that
invalidates fewer React Query keys than the queries its OWN live event handlers keep fresh.

```
grep -rn 'on("connect"' apps/mobile/src apps/admin/src --include=*.ts --include=*.tsx
grep -rn 'on("connect_error"' apps/mobile/src --include=*.ts
grep -rn 'useForegroundRefetch(' apps/mobile/app
grep -rn 'invalidateQueries' apps/mobile/src/realtime apps/mobile/app
```

Hits: every `socket.on("connect"/"connect_error")` site in `apps/mobile/src/realtime` (4 hooks:
`use-order-socket.ts`, `use-rider-job-socket.ts`, `use-rider-board.ts`, `use-rider-location.ts`) plus
every `useForegroundRefetch(...)` call site (4: `rider/index.tsx`, `rider/job.tsx`, `order/[id].tsx`,
`home.tsx`).

Disposition:
- `use-order-socket.ts` (`refetchOrder`) — already-guarded: invalidates the one query
  (`orderKey(orderId)`) its own live events (`orderStatus`) update; no second query in scope.
- `use-rider-job-socket.ts` (`refetchJob`) — already-guarded: invalidates `["activeJob"]`, the one
  query its own live events (`orderStatus`) update; no second query in scope.
- `use-rider-location.ts` — not a sibling of this class: its `connect` handler pushes the last-known
  position over the socket (a write, not a query self-heal) and holds no React Query cache at all.
- `use-rider-board.ts` — **the confirmed bug** (BH-13). Fixed.
- `rider/index.tsx`'s own `useForegroundRefetch` — **vulnerable sibling, same shape via a different
  self-heal path** (surfaced by the workflow's sweep). Fixed in the same commit.
- `rider/job.tsx`, `order/[id].tsx`, `home.tsx`'s `useForegroundRefetch` calls — already-guarded: each
  invalidates the one query its own screen owns (`activeJob`, the order snapshot + offers, and
  `activeCustomerOrder` respectively); no second query in scope for any of them.

**BH-14** — pattern signature: a SecureStore-restored draft/marker rehydrated on cold start with no
check against a server-side expiry/window the object it wraps carries.

```
grep -rn "void load[A-Za-z]*(.*)\.then(\|void Promise.all(\[load" apps/mobile/app --include=*.tsx
grep -rn "await load[A-Za-z]*(" apps/mobile/app --include=*.tsx
grep -rln "OFFER_WINDOW_MS" -r .
grep -rn "SecureStore.getItemAsync\|AsyncStorage" apps/mobile/src apps/admin/src apps/admin/app
```

Hits: 24 across the two greps for the load-on-mount idiom. Disposition — every OTHER durable marker
this codebase persists (`pendingRating`, `pendingSenderRating`, `confirmItemsPending`, `PendingTopup`,
`deliveryCodeAttempts`/`codeRotatedAt`) is reconciled against the LIVE server snapshot on every refresh
(`reconcile*` helpers keyed off the order's current status/fields from the API, not a client-side
clock), which is inherently self-correcting and was confirmed already-guarded. `rider-bid-draft.ts` is
the only one of this family that has no live snapshot to reconcile against (a not-yet-sent bid has no
server record at all) and instead needed the auction's own `createdAt + OFFER_WINDOW_MS` deadline as
the correctness source — the gap this fix closes. No other sibling found with the same shape (an
unbounded-lifetime local draft with a known, checkable expiry it never checked).
