# Design system — tokens, faces and error surfaces

How the design tokens reach the three apps, how they are kept in sync, and the rules for error
surfaces. For where each screen's design lives, read [`DESIGN.md`](./DESIGN.md).

## What lives where

| Path | Role |
|------|------|
| `packages/design/tokens/*.css` | **The token source of truth** (`colors.css`, `spacing.css`, `typography.css`, `icons.css`, `fonts.css`). |
| `packages/design/handoff/*` | Per-screen design authority. Each handoff has a ledger entry in [`DESIGN-DEVIATIONS.md`](./DESIGN-DEVIATIONS.md). |
| `packages/design/` (rest) | Gallery, UI kits, components, brand assets. A mirror of the design tool: never edit it to match the app. |
| `packages/shared/src/design-tokens.ts` | **Mobile face.** A TypeScript mirror of the CSS tokens (`color`, `semantic`, `space`, `radius`, `font`, `shadow`, `icon`, `leading`, `touchTargetMin`, `touchTargetPrimary`), imported by `apps/mobile` through `@lynia/shared`. |
| `apps/admin/app/globals.css` | **Admin face.** `:root` CSS variables. |
| `apps/merchant/app/globals.css` | **Merchant face.** `:root` CSS variables. The merchant app is a phone web app (360×720). |

`packages/design/_ds_bundle.js`, `_ds_manifest.json` and `_adherence.oxlintrc.json` are generated by
the design tooling. Don't hand-edit them.

## The accent split

The bright brand green fails text contrast, so green has three roles:

- **`--accent` / `accent`** (`#00b14f`): fills, graphics, map pins. Never text.
- **`--cta-fill` / `cta`** (`#00812f`): primary-button fills and any green fill that carries white text.
- **`--accent-text` / `accentText`** (`#006630`): green text and small icons.

Selected states use `--accent-wash` with `--accent-text`, never the CTA fill. Gold (`--highlight`)
never carries text; gold-family text uses `--highlight-ink` or `--highlight-chip-ink`.

## CSS ↔ TS token naming map

Same values, two spellings:

| CSS (`packages/design/tokens`) | TS (`design-tokens.ts`) | Admin / merchant CSS |
|---|---|---|
| `--cta-fill` | `cta` | `--cta-fill` |
| `--cta-fill-pressed` | `ctaPressed` | `--cta-fill-pressed` |
| `--accent-700` | `accentPressed` | `--accent-700` |
| `--space-2xl` / `--space-3xl` | `space.xxl` / `space.xxxl` | `--space-xxl` (neither face defines 3xl) |

Kebab-case CSS names become camelCase TS keys otherwise (`--accent-text` → `accentText`).

The RN `shadow` tokens are **approximations** of the layered CSS shadows. React Native can't draw
multi-layer box-shadows, so they match the visual weight, not the literal values. The drift test
skips shadow on the TS face and checks it on the CSS faces.

## Keeping tokens in sync

The guardrail is `apps/api/src/design-tokens.drift.spec.ts`. It parses every `--name: value;` in
`packages/design/tokens/*.css` and asserts that every token a face defines equals the design
source, across all three faces. A face may leave a token out; it may not disagree.

When a token changes in a new design export:

1. Change the app faces to match: `design-tokens.ts`, `apps/admin/app/globals.css`,
   `apps/merchant/app/globals.css`.
2. Never change `packages/design/tokens/*.css` to match an app. The `design-freeze` CI job
   (`scripts/check-design-freeze.mjs`) fails a PR that edits `packages/design/**` without a
   `DESIGN-DEVIATIONS.md` entry.
3. Update the core token table in [`DESIGN.md`](./DESIGN.md) if a listed value moved.

## Fonts, icons, brand (mobile)

- **Inter** 400/600/700 via `@expo-google-fonts/inter`. `src/ui/fonts.ts` patches `Text` and
  `TextInput` once to map each weight to its own family (Android matches families by exact name).
  A nested `Text` inherits its parent's family, so set the weight on the innermost span.
- **Lucide** icons through `src/ui/Icon.tsx` (`lucide-react-native` + `react-native-svg`).
- **Wordmark and dove** are vector paths (`src/ui/wordmark-paths.ts`, `src/ui/dove-paths.ts`,
  drawn by `src/ui/Brand.tsx`). No wordmark font loads at runtime.
- Admin self-hosts Inter with `@font-face` in its `globals.css`.

## Error surfaces — the four kinds, and which one you're allowed to build

Owner instruction, 2026-08-12: **"Error cards must just display once and go — which is when an
action is attempted and there is an error."**

| Kind | What it is | Treatment | Primitive |
|---|---|---|---|
| **Action error** | The user tapped something and it failed | Spoken **once** as a toast that dismisses itself after 2.5s (`TOAST_DURATION_MS`); never persists | `useActionError()` / `useActionErrorEffect()` in `src/ui/Toast.tsx` |
| **Field validation** | The value in this input is wrong | Stays inline until fixed | `Field`'s own `error` prop |
| **Content-slot state** | A screen's data didn't load | Calm couldn't-load state with Retry, in the content area, never red | `EmptyState` (`src/ui/EmptyState.tsx`, per `empty-states-v2-2026-10`, D-78) |
| **Connection status** | Network or socket is down | Calm strip that clears itself on reconnect | `OfflineBanner` |
| ~~**Background-poll error card**~~ | A poll the user never triggered failed | **Banned. Do not build it.** | none |

**Why the fifth row is banned.** It fires on work the user didn't ask for, on a timer. On a flaky link
it comes back again and again and covers a screen that otherwise works. The queries behind it heal on
their own poll and on reconnect, so a failed check simply shows nothing.

**The test for a new failure surface: did the user just tap something?** If yes, it is an action
error: toast it. If no, it belongs in the content slot, or it doesn't exist.

**Action-error details.** `useActionError` returns a `(message: string | null) => void`, the same
shape as the `setError` setters it replaced, so `setError(null)` is a harmless no-op. It raises on
**every** call, so a retry that fails with identical copy still speaks. For an error derived from a
mutation's `error` object, use `useActionErrorEffect(mutation.error)`: it keys on the Error object,
and React Query makes a fresh one per attempt. Both are pinned by
`apps/mobile/src/ui/__tests__/action-error.test.tsx`. They are hooks, so declare them above a
screen's early returns.
