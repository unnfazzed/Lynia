## Phase 1 — RF-19: merchant/dish/category ownership-lookup dedup

`merchant.service.ts`'s category and dish CRUD methods each repeated the same two-line shape —
`findFirst({ where: { id, merchantId } })` followed by `if (!x) throw new NotFoundException(...)` —
to confirm a category or dish row actually belongs to the calling merchant before reading its id or
mutating it. Six call sites shared the identical shape (four dish, two category):

- `updateCategory` — category-ownership check before building its partial update payload.
- `createDish` — category-ownership check (`body.categoryId` must belong to this merchant) before
  creating the dish under it.
- `updateDish` — dish-ownership check up front, plus a *second*, structurally identical
  category-ownership check nested inside the `if (body.categoryId !== undefined)` branch when the
  dish is being reassigned to a different category.
- `deleteDish` — dish-ownership check before deleting.
- `writeDishOutOfStock` (the private helper both `setDishOutOfStock`/`clearDishOutOfStock` call
  through) — dish-ownership check before writing `outOfStockUntil`.

Extracted two private helpers next to the existing `findOwnMerchantIdOrThrow`:

```ts
private async findOwnCategoryOrThrow(merchantId: string, categoryId: string): Promise<PlainCategoryRow> {
  const category = await this.prisma.merchantCategory.findFirst({ where: { id: categoryId, merchantId } });
  if (!category) throw new NotFoundException("Category not found");
  return category;
}

private async findOwnDishOrThrow(merchantId: string, dishId: string): Promise<DishRow> {
  const dish = await this.prisma.merchantDish.findFirst({ where: { id: dishId, merchantId } });
  if (!dish) throw new NotFoundException("Dish not found");
  return dish;
}
```

Each of the six call sites now delegates to one of these instead of inlining its own
`findFirst`/throw pair; the query shape (`where: { id, merchantId }`), the exact error message
(`"Category not found"` / `"Dish not found"`), and the exception type (`NotFoundException`) are all
unchanged — every call site's external behavior is byte-identical.

**Deliberately left untouched: `deleteCategory`.** Its own ownership `findFirst` also needs
`include: { _count: { select: { dishes: true } } }` to answer its own business rule ("a category is
deletable only once empty") — folding it into the plain two-helper shape would either lose that count
(forcing a second round-trip query, a real behavior/perf change no test would catch) or turn the
helper into an optional-include parameter, which relocates the special case into the shared helper
rather than removing it. Left as its own explicit `findFirst` + count check, same as before.
