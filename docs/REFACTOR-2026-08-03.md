## Phase 1 — RF-18: first scoped extraction from the food-order tracking screen

The ledger's own note on RF-18 said "full split is L effort (bigger than one PR); scope a first
extraction PR to 2-3 branches" — each of the ~9 `merchantPhase`/`status` branches in
`app/food/order/[orderId].tsx` (then 888 lines) is already a self-contained JSX view with no state
of its own, making them a clean split seam. Picked the **two cleanest, lowest-risk branches** for
this first PR:

- **`order.status === "cancelled"`** (55 lines, 3 sub-cases: D-13's NO_RIDER apology, a
  merchant-issued refund card, the generic cancelled card) — purely a function of `order` fields
  (`rejectionReason`/`refundedAt`/`refundAmount`/`refundReference`) plus `reachable`/
  `restaurantName` and two navigation callbacks. No hooks, no local state.
- **`order.status === "undelivered"`** (43 lines) — purely a function of `reachable`/
  `restaurantName`/`orderId` plus the tracking snapshot's `undeliveredReason`/`undeliveredAttempts`,
  and one navigation callback. Also no hooks, no local state.

Both were extracted **verbatim** (JSX, copy, and prop-driven logic byte-identical) into new
presentational components:

- `apps/mobile/src/ui/food/FoodOrderCancelledView.tsx` — takes `order` (a `Pick` of the 4 fields it
  reads), `restaurantName`, `reachable`, `onRetry`, `onBrowse`.
- `apps/mobile/src/ui/food/FoodOrderUndeliveredView.tsx` — takes `orderId`, `restaurantName`,
  `reachable`, `reason`, `attempts`, `onBackToBrowsing`.

Both branches (and 8 of the screen's other remaining branches) called two private helper
functions, `OrderHeader` and `Row`, that were defined at the bottom of the screen file. Since the
new view files need them too, they were lifted verbatim into a new shared module,
`apps/mobile/src/ui/food/FoodOrderHelpers.tsx`, and the main screen now imports them from there
instead of defining them locally — the remaining 8 in-file usages (awaiting_accept,
awaiting_item_approval, the 3 awaiting_payment sub-branches, preparing, ready_for_pickup, the live
tracker, and the unreachable safety-net fallback) are unaffected, same functions, same call sites.

The main screen's two branches now read as a one-line delegation each:

```tsx
if (order.status === "cancelled") {
  return (
    <FoodOrderCancelledView
      order={order}
      restaurantName={restaurantName}
      reachable={reachable}
      onRetry={() => router.replace(`/food/${order.merchantId}`)}
      onBrowse={() => router.replace("/food")}
    />
  );
}
```

Caught one thing while extracting: an earlier draft of the cancelled-refund sub-view stringified
`refundAmount` directly instead of calling `formatMoney` — fixed before it landed anywhere, so the
shipped diff renders the refund amount identically to before (`formatMoney(order.refundAmount ?? 0)`).
Also had to correct the extracted `UNDELIVERED_REASON_LABEL` import to its actual source
(`src/logic/order-labels`, not `@lynia/shared` — the constant is mobile-local, not a shared-package
export) to keep the moved code compiling against the same symbol the original file used.
