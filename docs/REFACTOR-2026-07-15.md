## What changed

**RF-01 — dead code: orphaned `clear*` wrappers** (kind: `dead-code`)
- `apps/mobile/src/logic/saved-recipients.ts`: removed `clearRecipients()`.
- `apps/mobile/src/net/history-store.ts`: removed `clearHistorySnapshot()`.
- Evidence: repo-wide grep (`apps/`, `packages/`) found zero call sites for either export
  beyond their own definitions. `apps/mobile/src/auth/session.ts`'s `clearDeviceState()` (the
  actual sign-out wipe) already deletes `RECIPIENTS_KEY` / `MY_PICKUP_PHONE_KEY` /
  `HISTORY_SNAPSHOT_KEY` directly via `SecureStore.deleteItemAsync(...)` — confirmed by reading
  `session.ts:435-440` — rather than calling these wrappers. No import site needed updating.
  Mobile-only, JS-only, OTA-able. 17 lines removed.
- Commit `bd83cae`.

**RF-03 — type the Text/TextInput font-patch** (kind: `type-safety`)
- `apps/mobile/src/ui/fonts.ts`: replaced every `any` (`(...args: any[])`, `as any` ×4,
  `props: any`, `ref: any`) with a named `PatchedRenderFn`/`Patchable` type pair. `original`,
  `patchedRender`, and the `__lyniaInterPatched`/`__lyniaOriginal` Fast-Refresh guard markers
  are now typed end to end instead of cast through `any`.
- Behavior-preserving: `apps/mobile/src/ui/__tests__/fonts.test.tsx` (10 tests covering weight
  mapping, the fast no-style path, style-array flattening, explicit-`fontFamily` passthrough,
  the throw-mid-render exactly-once-call guarantee, and the re-patch/Fast-Refresh guard) passes
  unchanged, pre- and post-refactor, with no test edits.
- Mobile-only, JS-only, OTA-able. 22 insertions / 10 deletions.
- Commit `b44e6db`.

**RF-02 — split `NotificationsService`'s feed read-model out of the push write path** —
**considered, not done this run.** `apps/api/src/notifications/notifications.service.ts` (612
lines) bundles push-fan-out/device-token registration with a ~220-line read-only `feedForUser`
in-app-feed derivation (plus its `NotificationRow`/`FEED_*` constants) that has no relationship
to the push path beyond living in the same class. It has strong, precisely-targeted test
coverage (`notifications.service.spec.ts`'s dedicated 13-test "derived in-app feed" block).
Estimated at ~470+ changed lines once the extraction + module/controller wiring is counted,
which is over this routine's ≤400-line-per-PR guidance and involves NestJS provider/controller
wiring — more risk than warranted for stacking onto a first run. Ledgered as **OPEN** with the
full extraction plan so the next run can pick it up directly (see ledger).
