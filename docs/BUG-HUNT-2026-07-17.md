**BH-15** — pattern signature: a cold-start bootstrap redirect that routes on session-presence alone,
bypassing a required onboarding step whose completion isn't captured durably.

```
grep -rn '"/profile/setup"' apps/mobile --include=*.tsx --include=*.ts
grep -rhoE 'router\.(replace|push)\(("[^"]*"|`[^`]*`|\{)' apps/mobile/app --include=*.tsx | sed -E 's/router\.(replace|push)\(//' | sort | uniq -c | sort -rn
grep -rn 'signIn\(' apps/mobile/app apps/mobile/src --include=*.tsx --include=*.ts
grep -rln 'Redirect href' apps/mobile/app --include=*.tsx
grep -rn 'needsProfile' apps/api/src apps/mobile --include=*.ts --include=*.tsx
grep -rn 'firstName:\s*""|lastName:\s*""|idNumber:\s*""' apps/api/src
grep -rn 'saveKycDraft|savePendingTopup|saveRolePreference|savePermissionsPrimed' apps/mobile/src/auth/session.ts apps/mobile/src/logic/kyc-draft.ts
```

41 hits. `index.tsx` is the ONLY screen in the app that makes a session-presence bootstrap routing
decision (`Redirect href` appears only there among cold-start-relevant files); every other screen
reached post-auth assumes the profile is already complete. `/profile/setup` has exactly one inbound
reference (`verify.tsx`), so there was one call site to fix, not a sibling class. Confirmed separately
that no admin-console write path for `firstName`/`lastName` exists anywhere in `apps/admin` or
`apps/api/src/admin` (grep returns only read/display usage) — the only other write path,
`PATCH /riders/profile` (`completeProfile`), is itself now reachable only through the fixed bootstrap.
