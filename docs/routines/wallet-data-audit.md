## Mission — prove the money & data lifecycle is correct end to end
Audit the full path a unit of money and a unit of reporting data travels, and fix what is broken:

  rider wallet (top-up → CommissionAccount.balance → append-only CommissionLedger)
  → per-ride commission debit on order completion
  → earnings the rider sees
  → the numbers the admin dashboard reports and the admin actions that mutate them.

The bar is: (a) **no transaction is lost, double-counted, or mis-recorded**; (b) **balances, earnings, and dashboard KPIs reconcile** with the append-only ledger and the underlying orders; and (c) **every admin action** (wallet-credit, fare-adjust, order cancel, customer hold/lift, rider suspend/lift/ban/clear-hold, KYC decision) **writes correct, authorized, audited, idempotent data**. This is about the data lifecycle being sound and payments being well integrated into the data + reporting lifecycle.

**Do NOT build new features.** This routine ships bug fixes and behavior-correcting UI/UX + data-integrity improvements only. If you spot a worthwhile feature, record it under a "Suggestions (not implemented)" heading in the report — do not implement it. **Do not defer any code fix** — fix everything you find in this run (universal policy: no postponed actions).
