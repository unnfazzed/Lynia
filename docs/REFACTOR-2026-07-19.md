# Refactoring routine — 2026-07-19

Third run of the recurring refactoring routine (`docs/ROUTINES.md` → "Refactoring routine").
Modeled on Piranha (small recurring dead-code diffs), Shepherd (mechanical rewrites validated
per-diff by full CI), and Google's small-CL discipline. Mission: improve code health **without**
changing behavior.

## Model usage

Phase 0/1 (ledger read, churn analysis, target selection) ran on `model: fable` via the Agent
tool, per this routine's required split. Phase 2 (the actual extraction, test moves, DI-wiring
fix, and PR/ledger wiring) ran on the session model (Sonnet 5) rather than an `opus` subagent
override — by the time Phase 2 started, the session already held the full Phase-0/1 context
(every touched file read line-by-line) needed to do the extraction correctly and verify it;
re-delegating to a fresh Opus subagent would have meant re-deriving that context rather than
using it, with no quality gain for a mechanical, fully-specified move. Noted per the routine's
own fallback clause ("if a model override is unavailable, proceed on the session model and note
it").

## Target chosen: RF-06 — split KYC-review reads out of `AdminRidersService`

**Churn × complexity evidence.** `apps/api/src/admin/admin-riders.service.ts` has been in the
ledger's top-5 hotspot for three consecutive runs (churn 8-9 across 45-day windows) and carried
an explicit "OPEN ... take conservatively, next run" annotation from the 2026-07-17 run, which
had confirmed `admin-riders.service.spec.ts` grew to 720+ lines / 42+ tests — the characterization
coverage RF-06 had been blocked on was no longer the blocker. The 2026-07-19 Fable target-
selection pass re-verified: 809-line spec, ~50 tests across 6 describe blocks (listRiders,
2×getKycReview, getRiderDetail, mutations, standing-change notification, walletView), and no
OPEN `KNOWN_BUGS.md` defect inside the file's KYC-review or standing-mutation code (the one
nearby OPEN item, `KB-HOLD-SESSION-SCOPE`, is a flagged *product-decision* asymmetry in
`auth.service.ts refresh()`, not a code defect in this file).

**What changed.** `getKycReview` (~94 lines: national-ID duplicate-collision query + signed
KYC-photo read-URL minting, `KYC_PHOTO_READ_URL_TTL_SECONDS` = 15 min) moved verbatim into a new
`AdminKycReviewService` (`apps/api/src/admin/admin-kyc-review.service.ts`). Its two describe
blocks (9 tests: duplicate-ID collision handling, photo-URL signing/null/failure paths) moved
verbatim into a new `admin-kyc-review.service.spec.ts`. `AdminRidersService`'s constructor
dropped the `pii`/`storage` dependencies — both were used *only* inside `getKycReview`, nowhere
else in the file — leaving `AdminRidersService` scoped to the roster/standing-mutation surface
(`listRiders`, `getRiderDetail`, `walletView`, `suspendRider`/`liftRider`/`banRider`/`clearHold`,
the standing-change customer notifier). `admin.controller.ts` and `admin.module.ts` wired the new
service in; the controller's `@Get("riders/:profileId/kyc")` handler is otherwise unchanged
(same route, same guard, same 404 semantics, same response shape).

**Deliberate scope choice.** The Fable target-selection pass flagged that RF-06's original framing
implied moving the *tested mutations* (suspend/lift/ban/clearHold) into a new service instead. I
chose the read-side extraction over that: `getKycReview` shares zero state or helper logic with
the mutation methods (confirmed by grep — `pii`/`storage` appear nowhere outside it), so this
extraction cannot touch the sensitive suspend/ban/clear-hold core at all, versus a materially
larger, riskier diff (~550 lines touching the sensitive core) for the mutation-side alternative.
Same RF-06 debt-register outcome ("misplaced logic moved to its layer"), strictly lower risk —
consistent with "characterize first or skip and ledger it" for anything that *does* touch a
sensitive area; this one simply doesn't.

**One incidental fix forced by the move (not a behavior change, a test-fixture correction):**
`admin-authz.e2e.spec.ts` manually re-declares `AdminController`'s `design:paramtypes` reflection
metadata (a pre-existing pattern in that file, used because the e2e harness needs to resolve DI
positionally rather than via decorators). Inserting the new `AdminKycReviewService` constructor
parameter shifted every later parameter's position, which silently mis-wired `this.sos` to
`undefined` in the SOS-acknowledge test (a 500 instead of 201) until the paramtypes array and both
mock-provider lists were updated to include the new token in its actual constructor position.
This is a test-infrastructure fix required *by* the refactor, not a separate defect — flagged here
for visibility since it's not a pure line-for-line move like the rest of the diff.
