# Dead-code removal — 2026-08-17

**Lane:** dead-code removal (*"deletes provably unreachable code"*). Ledger prefix **`DC-`**.

**Mission.** Delete code that is *provably* unreachable — and prove it, per finding, before deleting.
The bar is deliberately the same one the useless-test-pruning lane sets for a condemned test: a
candidate is condemned by **evidence**, never by a grep that came back quiet. This repo has already
paid for the alternative once — the 2026-08 copy-string "parity" audits reported ✅ while 243 of 244
screens were misaligned (`docs/UI-KIT-VS-SHIPPED-VISUAL-AUDIT-2026-08-05.md`).

For dead code the evidence is a **reachability table**: per candidate, every channel that could reach
it, what was found on each, and the verdict. A symbol is deleted only when every channel is empty.

## Baseline

`pnpm typecheck && pnpm test` were **red on first run for environment reasons only** — a fresh
`pnpm install` leaves the Prisma client ungenerated, so 200+ `Property 'x' does not exist on type
'PrismaService'` errors and 13 API suites fail. `pnpm --filter @lynia/api prisma:generate` turned both
green before any analysis began. This is the identical false red the 2026-08-16 flag-retirement run
recorded; it is an environment gap, not a defect on `main`.

Baseline after generate: **typecheck 0, tests 0** (1301 mobile tests / 168 suites, 100 API files, 29
merchant, 11 admin, 12 shared).

## Channels checked per candidate

A TypeScript import graph alone is not proof — this repo reaches code through at least six channels:

| # | Channel | Why it matters here |
|---|---|---|
| 1 | TS import graph | `dependency-cruiser` orphan rule — but its cruise **excludes spec files** and the committed root set **omits `apps/mobile/app`** (Expo Router), `apps/admin/middleware.ts` and `apps/api/scripts` |
| 2 | Framework file conventions | Expo Router screens and Next app-router `page`/`layout`/`route` files are invoked by filename, never imported |
| 3 | Dynamic string resolution | `tools/parity/render-mobile.mjs --fixture <name>` loads `mobile/fixtures/*.mjs` **by name** — 62 fixture files look unreferenced and are all live |
| 4 | CI / workflows | `.github/**` is **hidden**, so a default `rg` sweep silently skips it (this caught a false positive: `render-wired-mobile.mjs` is used by `ci.yml:158`) |
| 5 | Test-only importers | A module imported only by its own spec is either dead production code *or* a deliberate verification artifact — the two are opposite verdicts |
| 6 | Compiler reachability | `allowUnreachableCode` / `noUnusedLocals` prove statement-level deadness that no grep can |

Two of my own sweeps produced false positives before they were corrected (the hidden-file flaw in #4,
and a basename grep where `nav` matched half the repo). Both are recorded here because the corrected
result is the finding: **the naive version of this audit would have deleted live code.**

**`DC-01` — `apps/api/src/riders/kyc-decline-reasons.ts` (21 lines).** Zero importers on every channel,
including `--hidden`. It is a **superseded duplicate**: its own header carries `TODO(A-01)` saying the

## Reachability table — symbol-level candidates

314 exported symbols were checked for external references. 174 had none, but that alone is **not**
deadness: an exported symbol used inside its own file is *over-exported*, not unreachable, and ~124 of
those are prop/return types used one line below their declaration. Filtering to values unreferenced
*even within their own file* leaves **3**:

| Symbol | Verdict |
|---|---|
| `PRIVACY_URL` (`apps/mobile/src/config.ts`) | 🗑️ **DELETED — `DC-01`** |
| `sendFoodPaymentPrompt` (`apps/mobile/src/api/food-orders.ts`) | ⚠️ **KEEP — not dead: missing wire-up (`DC-02`)** |
| `checkFoodPaymentPrompt` (`apps/mobile/src/api/food-orders.ts`) | ⚠️ **KEEP — not dead: missing wire-up (`DC-02`)** |

**`PRIVACY_URL`.** Unreferenced on every channel. The app never links the API-served `/legal/privacy`
page: the Settings row opens the **drawn in-app notice** `/settings/privacy` (LJ.privacy), and Play
Console's "Privacy policy" field is a *listing* value entered by hand from
`docs/PLAY-STORE-SUBMISSION.md`. The constant's own comment had gone stale — it claimed "the Settings
screen links it in-app", which is no longer true. Notably the same comment already documents the
correct precedent for its `/legal/account-deletion` sibling: *"the app never links it … It therefore
has no constant here."* By the file's own rule this constant should not exist. The API still serves
both pages; only the unused client constant is gone, so the Play Console URL remains valid.

**`DC-02` — the payment-prompt pair is NOT dead code.** This is the finding that most rewarded
checking, and the reason the depcruise rule's own comment says an unreferenced module is *"usually dead
code **or a missing wire-up**"*. Every surrounding piece of the feature is live:

- the API serves both endpoints — `food-order.controller.ts:69` `POST orders/:orderId/payment-prompt`
  and `:79` `POST orders/:orderId/payment-prompt/check`;
- `PaymentPromptRail` is a live shared type, and the service tracks a documented prompt lifecycle;
- `apps/mobile/CHANGELOG.md` records the flow as shipped (#670 / #687);
- the mocks draw `RC.pay_now`, `RC.pay_wait`, `RC.pay_confirmed`, all three **current** in
  `tools/parity/screens.generated.json`;
- `tools/parity/parity-status.mjs:91` allowlists `RC.pay_wait` as **`PENDING`** with the comment
  *"#670: paymentPromptStatus=\"pending\" renders this; renderable from a fixture now."*

So the client functions are the API half of a screen the parity registry is **actively waiting on**.
Deleting them would have destroyed shipped work, made a tracked gap invisible, and left a `PENDING`
screen with nothing to wire. Ledgered as **`DC-02` (OPEN)** for the screen lane instead. Under
CLAUDE.md's "not drawn ⇒ not rendered" rule this is the mirror case: it **is** drawn, so it should be
rendered — the fix is to wire it, not to delete it.

## Compiler-proved reachability

Grep cannot prove statement-level deadness, so the compiler was asked directly: `allowUnreachableCode:
false` + `noUnusedLocals: true` were enabled and the monorepo typechecked.

| Check | Result |
|---|---|
| `TS7027` unreachable statement | **0 across all six packages** — there is no unreachable-after-`return`/`throw` code in this repo |
| `TS6133` unused local, **production** | **0** |
| `TS6133` unused local, tests | 62, every one `import React from "react";` in `apps/mobile` |

The 62 are genuinely dead: `apps/mobile/tsconfig.json` sets `"jsx": "react-jsx"` (automatic runtime),
so JSX compiles to `react/jsx-runtime` calls and needs no `React` binding in scope. One of the 62 is
dead for a second reason — `src/ui/rider/__tests__/top-up-flow.test.tsx:30` declares its own local
`const React = jest.requireActual(...)`, which shadowed the import outright. All 62 removed; the full
suite passes unchanged.

**These two options are now ON permanently in `tsconfig.base.json`.** This is the durable half of the
run and follows the owner's standing instruction to *"put guardrails to make sure"* rather than rely on
a repeated audit: the repo is provably clean of both classes today, and CI now fails the moment either
returns. A future dead-code pass should not have to rediscover what a compiler flag can prevent.
